## Browser shortcuts

SyncNos provides three browser actions: **open the popup**, **save the current page**, and **open/focus the SyncNos app**.

No keys are assigned by default. Use **Settings → Keyboard shortcuts** to see the current bindings or open the browser's extension shortcut settings.

## In-app shortcuts

Open **SyncNos → Settings → Keyboard shortcuts** to configure actions in the library, source/site filters, detail toolbar, More menu, and reader.

- Search for actions or key bindings, grouped by Navigation, Library, Details, and Reader. Click a key binding to record; the keys being pressed appear immediately.
- Supports letters, digits, punctuation, Space, Enter, Tab, Backspace, Delete, navigation keys, the numpad, F1–F24 and more. Left/right Command, Control, Option/Alt and Shift can be assigned independently as parts of a combination. Bare Tab and Escape are reserved for keyboard navigation and canceling recording.
- Use `×` beside a binding to clear it; press Escape to cancel recording. Backspace and Delete can be recorded as actual shortcuts. Duplicate and overlapping bindings are rejected; restoring defaults is also available.
- Key names adapt to macOS (`⌘`, `⌥`, `⌃`, `⇧`), Windows (`Ctrl`, `Alt`, `Win`) and Linux (`Ctrl`, `Alt`, `Super`), with `L` and `R` identifying the physical side. The primary `Mod` key means Command on macOS and Control on Windows/Linux.
- Common defaults remain available, including `Alt+Shift+B` to toggle the sidebar, `Alt+Shift+F` for the source filter, and `Alt+Shift+M` for the detail More menu. Bindings work only inside the SyncNos popup/app, not in inputs, editors or modal dialogs. System/browser-reserved combinations cannot be intercepted, and keys such as Fn, power or some media keys may never reach a webpage.

Hover over icon-only actions to see their names, with active shortcuts on a separate, subtler line. Menu items already labeled with text show only an assigned key; the Settings gear does not repeat “Open settings”.

## Images

AI chats and web articles can cache content images. Image failures do not block text capture; existing items can retry from **More → Cache images**.
