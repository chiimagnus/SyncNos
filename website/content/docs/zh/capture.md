## 先看采集方式

| 内容 | 默认方式 |
| --- | --- |
| AI 对话 | 因站点而异：ChatGPT / Google AI Studio 手动，其它支持站点可自动保存 |
| 网页文章 | 手动采集 |
| YouTube / Bilibili 视频内容 | 手动采集 |

无论来源是什么，采集结果都会先写入 SyncNos 本地库。

## AI 对话

当前支持：

| 平台 | 默认采集方式 |
| --- | --- |
| ChatGPT | 手动采集 |
| Gemini | 可自动保存 |
| Google AI Studio | 手动采集 |
| DeepSeek | 可自动保存 |
| Kimi | 可自动保存 |
| 豆包 | 可自动保存 |
| 元宝 | 可自动保存 |
| Poe | 可自动保存 |
| Notion AI | 可自动保存 |
| z.ai | 可自动保存 |

**ChatGPT 与 Google AI Studio 使用虚拟列表。**离开视口的历史轮次可能不在当前 DOM 中，因此 SyncNos 不把它们加入普通自动保存，而是在你主动采集时执行完整性准备流程。

ChatGPT 还提供可选的**高级采集**。显式开启后，手动采集可使用当前已登录 ChatGPT 会话请求当前对话数据；它仍然只在你主动保存时运行，不会变成后台轮询或自动采集。遇到 ChatGPT 新增的未知后端内容结构时，SyncNos 会保留能够安全归属的内容，并把结果标记为部分采集；如果会话身份或消息树本身无法可靠确认，则直接失败而不是猜测。高级采集失败时不会在同一次保存中静默回退 DOM；需要 DOM 路径时关闭开关后再次保存。

## 网页文章

网页文章由用户主动采集。SyncNos 会尝试提取正文，以及标题、URL、作者、发布时间等可用元数据，并转换成适合本地阅读和导出的 Markdown。

部分站点有专门处理逻辑。图片下载失败不会阻止正文保存。

## 视频内容

YouTube 和 Bilibili 视频页支持保存当前页面内容，并采集页面已经加载的字幕 / transcript；来源提供时间信息时会一并保留。

SyncNos 不生成不存在的字幕，也不下载音视频流。即使当前没有字幕，受支持的视频仍可以作为 Video 保存。

## 图片缓存

AI 对话和网页文章都可以把图片缓存到本地。正文保存与图片下载相互独立，因此图片失败不会把已经成功保存的正文判成失败。

对于 ChatGPT，用户上传图片和 AI 生成图片属于对话内容；普通工具截图、视觉执行产物不会作为对话图片保存。开启“自动保存 AI 对话图片到本地”后，SyncNos 会先保存对话，再在后台缓存图片；关闭时，未缓存的 ChatGPT 图片仍可在当前登录状态允许时按需显示。已有条目也可以在详情页“更多”菜单中手动点击**缓存图片**。

对于网页文章，“自动保存网页文章图片到本地”控制普通图片缓存；命中防盗链规则时，SyncNos 可以带所需 Referer 强制尝试缓存原图。

导出或 Provider 同步需要图片时，也可以临时取得尚未本地缓存的 ChatGPT 图片，而不要求先把它永久缓存。详见[导出与备份](/docs/export-backup/)和[同步到外部服务](/docs/sync/)。

## 采集之后

- 为文章添加高亮、评论和回复；
- [同步到外部服务](/docs/sync/)；
- [导出 Markdown / JSON 或创建 Backup](/docs/export-backup/)。
