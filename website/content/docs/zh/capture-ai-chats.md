## 支持的平台

| 平台 | 保存方式 |
| --- | --- |
| ChatGPT | 手动保存 |
| Gemini | 可自动保存 |
| Google AI Studio | 手动保存 |
| DeepSeek | 可自动保存 |
| Kimi | 可自动保存 |
| 豆包 | 可自动保存 |
| 元宝 | 可自动保存 |
| Poe | 可自动保存 |
| Notion AI | 可自动保存 |
| z.ai | 可自动保存 |

ChatGPT 和 Google AI Studio 使用虚拟列表，完整历史不一定同时存在于页面中，因此不参与自动保存。

## 手动保存

1. 打开目标对话，并切换到要保存的线程。
2. 在 SyncNos Popup 中选择**抓取 AI 对话**，或使用右键菜单的**保存当前 AI 对话**。
3. 回到[本地库](/docs/library/)确认对话和消息。

对支持自动保存的平台，可在**设置 → 通用 → 自动保存**开启后续消息的自动保存。

## ChatGPT 高级采集

在**设置 → 通用 → ChatGPT 高级采集**中，手动保存会以 ChatGPT 后端当前分支作为历史真源。引用会转换为可读的 Markdown 链接，图表等富内容只保留适合长期保存的标题与说明，不会把 ChatGPT 内部传输标记或组件数据原样写进正文。

如果最后一轮还在思考或生成，已有稳定轮次身份的思考摘要、进度和当前可见回复会作为“待确认”的部分结果保存；回复完成后再次保存即可由后端最终内容收敛，不会保留临时重复消息。某一轮即使没有 final 回复，只要随后已经进入下一条用户消息，其中可见且具有稳定轮次身份的思考与进度也会作为历史保留。

高级采集失败时不会在同一次保存中静默改走整段页面采集。关闭这个开关后重新保存，即可回到默认页面采集路径。

当支持的平台已经识别、但页面中还没有可保存的消息时，Popup 会显示“等待消息”，而不是把它当成抓取错误。部分保存也会区分“历史完整性待确认”“实时回复仍在变化”等原因。

## 图片与本地复用

AI 对话图片可以自动缓存到本地；关闭自动缓存后，正文仍然可以保存。

保存完成后，还可以使用[$ 插入](/docs/dollar-mention/)把本地条目重新插入支持的 AI 输入框。
